## Стратегия 

Цель данной библиотеки - обработка энкодера с наименьшими затратами времени и памяти МК. Первоначально данная библиотека разрабатывалась для энкодеров EC11 типа, и его исполнений на плате по типу Type 2. Но также эту библиотеку можно использовать для обычных энкодеров но в пределах частоты вызова update().
Данная библиотека не имеет программного фильтра помех (по причине оптимизации), данная задача должна возлагается на аппаратную часть путем подтяжки к земле или к питанию с использованию конденсаторов и резисторов необходимого номинала.

## Аргументы класса

LL_Encoder_T2c("Канал А или S1", "Канал B или S2", "Key", "Режим для каналов A и B (S1, S2)", "Режим для Key") "Имя объекта";

В "Канал А или S1", "Канал B или S2", "Key" указываем номера пинов так как они указанны на плате Arduino Nano к примеру если решили подключить энкодер Type 2 к входам D4 D5 D6, S1 на D4 а S2 на D5 Key на D6 то в аргументы указываем LL_Encoder_T2c(4, 5, 6, "Режим для каналов A и B (S1, S2), "Режим для Key") "Имя объекта";.

В "Режим для каналов A и B (S1, S2)" Указываем режим работы GPIO для "Канал А или S1", "Канал B или S2".

В "Режим для Key" Указываем режим работы GPIO для "Key".

В "Имя объекта" Указываете любое желаемое имя объекта класса.

## Режимы GPIO

Библиотека поддерживает три основных режима настройки GPIO для каналов A, B и Key: LL_INPUT, LL_INPUT_PULLUP, LL_EXTERNAL_PULLUP.
При выборе номеров пинов необходимо учитывать следующие ограничения:
Каналы A (S1) и B (S2) должны находиться в одном регистре GPIO: либо D2–D7 (PIND), либо D8–D13 (PINB). Это сделано для оптимизации обработки сигналов энкодера.
Все три пина — A, B и Key — должны иметь разные номера.
Для подключения каналов A, B и Key разрешены только пины D2–D13. Пины D0 и D1, используемые для RX/TX, не поддерживаются.
При нарушении ограничений компилятор выдаст ошибку. Например, если каналы A и B находятся в разных диапазонах, появится сообщение Invalid pin combination. Both pins must be either 2-7 or 8-13.



### LL_INPUT

Прямое чтение GPIO без внутренней подтяжки в МК. Позволяет подключить выхода энкодера напрямую в GPIO МК но в данном случае высока вероятность дребезга и наводок на линии что приведет к некорректной работе. Данный режим также поддерживает аппаратный Pull-down подтяжку через резистор и конденсатор - в этом случае требуется выхода энкодера A, B и Key подключить через резисторы параллельно с конденсаторами к земле и параллельно к GPIO МК, как показано на примере схеме далее:

    Питание (VCC / e.g. +5V)
         │
       ┌─┴─┐
       │   │  A,B или Key выход энкодера
       └─┬─┘
         │
         ├───[ Пин Микроконтроллера (Вход) GPIO ]
         │
         ├───┐
         │   │
        [R] [C]  Параллельно: Резистор R (10 кОм) и Конденсатор C (0.1 мкФ)
         │   │
         └───┤
             │
            ─┴─  Земля (GND)

### LL_INPUT_PULLUP

В этом режиме включается внутренний подтягивающий резистор микроконтроллера между GPIO и VCC, благодаря чему при разомкнутом контакте на входе устанавливается высокий логический уровень (HIGH).

Для корректной работы энкодер при срабатывании должен замыкать вход GPIO на землю (GND). То есть общий контакт энкодера должен быть подключён к GND, а не к питанию.

Для подавления дребезга контактов рекомендуется использовать аппаратный фильтр на основе резистора и конденсатора.

### LL_EXTERNAL_PULLUP

В этом режиме внутренние подтягивающие резисторы микроконтроллера отключены. Для формирования высокого логического уровня используется внешняя подтяжка входа к питанию (VCC) через резистор.

Такая схема широко применяется в готовых модулях энкодеров EC11 Type 2, в том числе в распространённых круглых китайских модулях. Если на плате модуля уже предусмотрены внешние подтягивающие резисторы, обычно следует выбрать режим LL_EXTERNAL_PULLUP.

Пример подключения одного канала энкодера с внешней подтяжкой и RC-фильтром:

    Питание (VCC / e.g. +5V)
         │
        [R]  Резистор  
         │
         ├──────────────[ Пин Микроконтроллера (Вход) ]
         │                         │
         │                        [C] Конденсатор 
         │                         │
         │                         │
         │                       ──┴── GND
         │
       ┌─┴─┐
       │   │  A, B или Key — контакт энкодера
       └─┬─┘
         │
        ─┴─  Земля (GND)

## Основные методы класса

## Метод begin()

Данный метод производит инициализацию и настройку GPIO в соответствии выбранного режима и адресов пинов. Данный метод следует вызывать в области void setup().


### Метод update()

Основной метод обработки сигнала с энкодера. Работает по прицепу автомата Мили.

Граф состояний энкодера (Mealy State Machine)
Состояние ожидания

    State 0

        Encoder_Input == Mask_S1 -> переход в State 1 (старт по часовой стрелке)

        Encoder_Input == Mask_S2 -> переход в State 10 (старт против часовой стрелки)

Ветвь 1: Вращение по часовой стрелке (Clockwise)

    State 1

        Encoder_Input == inver_Mask_Encoder -> переход в State 2

        Encoder_Input == Mask_Encoder -> сброс в State 0

    State 2

        Encoder_Input == Mask_S2 -> переход в State 3

        Encoder_Input == Mask_S1 -> откат в State 1

        Encoder_Input == Mask_Encoder -> сброс в State 0

    State 3 (Завершение цикла по часовой)

        Encoder_Input == Mask_Encoder && !Key_Input -> Count++, Pulse_Right = true, возврат в State 0

        Encoder_Input == Mask_Encoder && Key_Input -> Count_with_Key++, Pulse_Right_Key = true, возврат в State 0

        Encoder_Input == Mask_S1 -> откат в State 1

        Encoder_Input == inver_Mask_Encoder -> откат в State 2

Ветвь 2: Вращение против часовой стрелки (Counter-clockwise)

    State 10

        Encoder_Input == inver_Mask_Encoder -> переход в State 12

        Encoder_Input == Mask_Encoder -> сброс в State 0

    State 12

        Encoder_Input == Mask_S1 -> переход в State 13

        Encoder_Input == Mask_S2 -> откат в State 10

        Encoder_Input == Mask_Encoder -> сброс в State 0

    State 13 (Завершение цикла против часовой)

        Encoder_Input == Mask_Encoder && !Key_Input -> Count--, Pulse_Left = true, возврат в State 0

        Encoder_Input == Mask_Encoder && Key_Input -> Count_with_Key--, Pulse_Left_Key = true, возврат в State 0

        Encoder_Input == Mask_S2 -> сброс в State 0

        Encoder_Input == inver_Mask_Encoder -> откат в State 12

### Метод GetCount()

Возвращает значения счетчика насчитанного без высокого уровня на пине "Key" в формате uint8_t от 0 до 255 в циклическом переполнении.

### Метод GetPulseRight()

Возвращает состояния направления вращения вправо без высокого уровня на пине "Key" в формате bool. 
GetPulseRight() сбрасываются в false при каждом вызове update(), а затем могут стать true, если в этом вызове завершился цикл энкодера.

### Метод GetPulseLeft()

Возвращает состояния направления вращения влево без высокого уровня на пине "Key" в формате bool.
GetPulseLeft() сбрасываются в false при каждом вызове update(), а затем могут стать true, если в этом вызове завершился цикл энкодера.

### Метод GetDirectionCode()

Возвращает состояния направления вращения без высокого уровня на пине "Key" в формате uint8_t.
При вращении вправо 0b00000001.
При вращении влево 0b00000010.

### Метод GetKeyState()

Возвращает состояния "Key" в формате bool.

### Метод GetCountKey()

Возвращает значения счетчика в формате uint8_t от 0 до 255  в циклическом переполнении.
Счётчик метода GetCountKey() изменяется, если в момент завершения цикла энкодера с высоким уровнем на пине "Key".

### Метод GetPulseRightKey()

Возвращает состояния направления вращения вправо вместе с высоким уровнем на пине "Key" в формате bool.
GetPulseRightKey() сбрасываются в false при каждом вызове update(), а затем могут стать true, если в этом вызове завершился цикл энкодера.

### Метод GetPulseLeftKey()

Возвращает состояния направления вращения влево вместе с высоким уровнем на пине "Key" в формате bool.
GetPulseLeftKey() сбрасываются в false при каждом вызове update(), а затем могут стать true, если в этом вызове завершился цикл энкодера.

### Метод GetDirectionCodeKey()

Возвращает состояния направления вращения вместе с высоким уровнем на пине "Key" в формате uint8_t.
При вращении вправо 0b00000001.
При вращении влево 0b00000010.

### Метод ResetCount()

Производит сброс счетчика у метода GetCount() в 0.

### Метод ResetCountKey()

Производит сброс счетчика у метода GetCountKey() в 0.

## Особенности и возможные проблемы

### Не верно выбранный режим GPIO

При неверно выбранном режиме GPIO - автомат Мили может считать некорректно сдвигая фазу счета в право или в лево в зависимости от вращения. 
При этом может казаться что счетчик работает верно. Но при перехоже с на один щечек в право лево право лево (или наоборот) можно будет наблюдать что счет завис на одном весте и не производит не производит инкремента - декрементацию на единицу.

### Предупреждения компилятора (`if constexpr`)

При компиляции на плате Arduino Nano `arduino:avr` Вы можете увидеть в логе предупреждения такого вида:

`warning: 'if constexpr' only available with -std=c++1z or -std=gnu++1z`

В коде библиотеки используется конструкция if constexpr, стандартизированная в C++17. При компиляции для Arduino Nano на базе ATmega328P с настройками по умолчанию может появляться предупреждение о том, что if constexpr доступен только в режимах -std=c++17 или -std=gnu++17.
При этом используемая версия AVR GCC поддерживает эту конструкцию как расширение языка даже при сборке с -std=gnu++11.
Проверенная конфигурация:
Плата: Arduino Nano, ATmega328P.
Arduino AVR Boards: 1.8.8.
AVR GCC: 7.3.
Флаги компиляции: -std=gnu++11.
В этой конфигурации библиотека успешно компилируется, несмотря на предупреждение. Совместимость с другими версиями компилятора и настройками сборки отдельно не проверялась.

### Особенности порядка битов GPIO

При обработке сигналов энкодера библиотека учитывает порядок битов в регистрах GPIO микроконтроллера AVR. Порядок расположения каналов A (S1) и B (S2) в регистре не обязан совпадать с порядком их обозначения в документации энкодера.

Например, если S1 подключён к младшему биту регистра, а S2 — к следующему, то при чтении регистра комбинация сигналов будет представлена в порядке битов S2, S1, а не S1, S2.

Для корректной работы библиотека на этапе компиляции формирует маски `Mask_Encoder`, `inver_Mask_Encoder`, `Mask_S1` и `Mask_S2` с учётом выбранного режима GPIO. В режимах `LL_INPUT_PULLUP` и `LL_EXTERNAL_PULLUP` логика обработки отличается от режима `LL_INPUT`, поскольку меняется активный логический уровень сигналов.

Эти преобразования выполняются внутри библиотеки и не требуют дополнительных действий со стороны пользователя. При соблюдении ограничений на подключение пинов порядок битов не влияет на использование публичных методов класса.
